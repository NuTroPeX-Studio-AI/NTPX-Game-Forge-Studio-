# Game Development Ecosystem Catalog

**Project:** NTPX GameForge Studio Lab

This is the canonical human-readable catalog of game-development technologies that GameForge may discover, route to, or integrate through adapters.

> Scope: “every game developer” is not a finite technical list if interpreted as every individual developer or studio. This catalog captures the engines, frameworks, creator platforms, platform SDK ecosystems, middleware, development environments, and supporting tools relevant to the Studio Lab architecture.

## Color / type key

- 🟥 AAA / high-end engines
- 🟦 general-purpose engines
- 🟩 open-source engines and code-first frameworks
- 🟪 no-code / low-code creators
- 🟧 browser / WebGPU / JavaScript engines
- 🟨 platform, console, and UGC ecosystems
- 🥽 VR / AR / XR
- ⬜ supporting production tools/middleware
- 🧩 specialized engines/runtimes

## 🤖 AI-assisted game-development roles

GameForge treats AI as an orchestration and workforce layer rather than a single engine. The registry architecture must support:

- coding agents
- game-engine/editor agents
- NPC/dialogue agents
- world-generation agents
- asset-generation agents
- animation agents
- voice/audio agents
- QA/playtest agents
- director/orchestration agents
- security/reviewer agents

## GameForge integration policy

GameForge does **not** bundle proprietary engines or restricted SDKs into the shared core. A technology becomes actionable only through a governed adapter using supported APIs, CLIs, plugins, SDKs, MCP servers, or automation surfaces.

For runtime state, distinguish:

- `KNOWN`
- `INSTALLED`
- `LICENSED`
- `AUTHENTICATED`
- `CALLABLE`
- `GOVERNED`

For feature mapping, distinguish:

- `REQUIRED`
- `SUPPORTED`
- `PARTIALLY_SUPPORTED`
- `EMULATED`
- `UNSUPPORTED`

No registry entry is permission to execute, redistribute, publish, or access a restricted SDK.
